## Common terminology
- **Machine learning (ML**) is the science of programming computers so they can **learn from data**.
- **Training set**: the examples that the system uses to learn.
- **Training instance** or **sample**: one example in a training set, represented by a set of features.
- **Feature**: one measurable characteristic or input variable of a training instance.
	- Sometimes called **predictors** or **attributes**.
- **Model**: the part of an ML system that learns and makes predictions.
- **Accuracy**: a performance measure often used in classification tasks
	- E.g., e-mails correctly classified as spam (by detecting unusually frequent patterns of words). 
- **Sampling bias**: a sample composed with a non-suitable sampling method.
- **Feature engineering**: the process of finding the right features to train on. The steps involved are:
	- **Feature selection**: selecting the most useful features.
	- **Feature extraction**: combining existing features to produce a more useful one.
	- Creating new features by gathering new data.
- **Data mining**: Discovering hidden patters in data.
- **Label**: the correct output associated with a training instance. The term is used mainly in **classification** tasks.
- **Target**: the correct output associated with a training instance. The term is used mainly in **regression** tasks.
- **Hyperparameter**: is a parameter of the learning algorithm (not of the model).
	- It must be set prior to training and remains constant during training.
## ML
- ML is very well suited for:
	- Problems for which existing solutions require a lot of work and maintenance.
		- E.g., long lists of rules for classifying spam/ham.
	- Complex problems for which using a traditional approach yield no good solutions.
		- E.g., speech recognition.
	- Fluctuating environments.
		- E.g. retraining a spam filter on new data.
	- Getting insights about complex problems and large amounts of data.
		- E.g. data mining.
## Training supervision

### Supervised learning
- The training set includes the labels.
- Typical tasks:
	- **Classification**: predicting a **class**.
		- E.g., spam/ham for an e-mail.
	- **Regression**: predicting a **target** numerical.
		- E.g., the price of car based on its features.
	- **Logistic regression**: regression algorithm that can be used for classification.
		- Outputs the probability of belonging to a class.
### Unsupervised learning
- The training set doesn't include labels.
- Typical tasks:
	- **Clustering**: finds groups within the data.
		- E.g., groups of similar visitors of a website.
	- **Hierarchical clustering**: can subdivide groups into smaller ones.
	- **Visualization**: output 2D or 3D representations of data.
	- **Dimensionality reduction**: simplifies data without losing too much information.
		- E.g., merging several correlated features into one (feature extraction).
	- **Anomaly detection**: finds data that differs from the data it was trained on.
		- E.g., unusual credit card transactions.
	- **Novelty detection**: aims to detect new instances that differ from all the training instances.
		- Similar to anomaly detection. However, its training set should contain **only normal observations**, whereas an anomaly-detection training set **may contain outliers** that the algorithm attempts to identify (and possibly flag).
	- **Association rule learning**: discovers relations between features.
		- E.g., if people buy product A and B then usually they also buy C.
### Semi-supervised learning
- The training set is partially labelled.
- E.g., in Google Photos individual persons are grouped (unsupervised; clustering), the user is asked to name (label) each person and then these labels are applied to all instances.
- Once the whole dataset is labeled, it can be used for supervised learning.
### Self-supervised learning
- Creates labels or targets from the data itself.
- Masks part of a training instance (input) and uses the unmasked training instance as a label.
	- E.g. masking part of an image or sentence and predicting the missing part.
- Can be used in **transfer learning**.
	- E.g., learns to 'repair' images of different animals. Thereby learning what a species looks like. Then this model is provided with pictures of different specimen and their labels. Thereby learning to classify (name) the species depicted on an image.
### Reinforcement learning
- The learning system (**agent**) can **observe** the environment, select and perform **actions** and get **rewards** or **penalties** in return.
- **Policy**: defines what action an agent should choose when it is in a given situation.
- It learns itself the best strategy (**policy**) to get the most rewards over time.
## Batch vs online learning
### Batch learning
- **Offline learning**: the system is trained and then launched into production, where it runs **without learning** anymore and only applies what it has learned.
- The system must (each time) be trained using **all available data**.
- Because of the time and computing resources this is usually done offline.
- **Data drift** or **model rot**: the (slow) decay of a model's performance over time. This is due to changes in the environment which are lacking in the training data.
- Updating a batch learning system means updating the training data and training a new version of the model.
### Online learning
- The system is **trained incrementally** by feeding it data instances sequentially; either individually or in small groups (**mini batches**).
- This is useful for systems that:
	- Need to rapidly adapt to change, e.g. detect new patterns in the stock market.
	- Need to learn autonomously and have limited computing resources, e.g. if a model is trained on a mobile device.
	- Need to be trained on huge datasets that cannot fit in one machine's memory (**out-of-core learning**).
		- Out-of-core learning is usually done offline.
- **Learning rate**: how fast the system should adapt to changing data. **???**
- **Catastrophic forgetting** or **catastrophic interference**: systems with a **high** learning rate tend to forget old data quickly.
- If bad data is fed to the system, the system's performance will decline. Therefore you need to monitor both the sanity of the input data and the model's performance.
## Instance-based versus model-based learning

### Instance-based learning
- The system learns the training data **by heart**, then generalizes to new cases by using a **similarity measure** to compare them to the learned examples.
	- E.g., **$k$-nearest neighbors regression** looks at the $k$ training instances closest to a new instance and predicts its target value, typically by averaging the target values of those neighbors.
- This works well for small datasets, especially if the data keeps changing.
- Since all training data needs to be deployed it does not scale or perform very well. Also it doesn't work well with high-dimensional data such as images.
### Model-based learning
- Generalizes from a set of examples by building a **model** of these examples and then uses that model to make **predictions**.
- **Model parameters**: designated with $\theta_0, \theta_1, \ldots, \theta_n$
- The model parameters are defined by the **learning algorithm**. **???**
- In order to do this, the learning algorithm requires a **performance measure**, either a utility or a cost function.
- **Utility function** or **fitness function**: measures how **good** the model performs.
- **Cost function** or **loss function**: measures how **bad** the model performs.
- **Training a model**: providing a **learning algorithm** (or **training method**) with training data so it can find the model parameters that make the model best fit the data.
	- E.g., a lineair regression algorithm that finds model parameter values that minimize a cost function.
- **Inference**: a trained and deployed model making a prediction.

## Main challenges of ML
### Bad data
- Insufficient quantity of training data.
	- Very different ML algorithms have comparable performance, if given enough training data.
- Nonrepresentative training data.
	- It is crucial to use a training set that is representative of the cases you want to generalize to.
	- If the sample is too small you will have sampling noise.
	- Also large samples can be flawed because of sampling bias.
- Poor quality data.
	- Data full of errors, outliers and noise.
	- Obvious outliers could be omitted or fixed.
	- In case of instances missing certain features:
		- The features could be ignored completely.
		- The instances could be ignored.
		- The missing features could be filled, e.g. interpolated.
		- Train two models; one with and one without the features and compare them.
- Irrelevant features.
	- The training data should contain enough relevant features and not too many irrelevant ones.
	- Requires proper feature engineering.
### Bad model
- **Overfitting** the training data.
	- Means that a model performs wel on the training data, but does not generalize well.
	- If the training set contains [[Basisbegrippen#Sampling noise|sampling noise]], the model is likely to detect patterns in the noise itself.
	- Overfitting happens when a model is **too complex** relative to the **amount and noisiness** of the training data, so it starts to learn these random patterns.
	- Possible solutions:
		- Simplify the model by selecting one with fewer parameters.
		- Reduce the number of attributes in the training data.
		- Constrain the model.
		- Gather more training data.
		- Reduce the noise in the training data.
	- **Regularization**: constraining a model to make it simpler and reduce the risk of overfitting.
		- E.g., reduce the [[1. Vrijheidsgraden|degrees of freedom]] in a lineair model from $2$ to $1$ or restrict the range of one of the parameters.
		- The amount of regularization can be controlled by a hyperparameter.
- **Underfitting** the training data
	- Means that the model is too simple to learn underlying structure.
	- Possible solutions:
		- Select a more powerful model, with more parameters.
		- Improve feature engineering.
		- Reduce the constraints on the model, e.g. the regularization hyperparameter.
## Deployment issues
- Possible issues during deployment are that the model:
	- Is too complex to maintain.
	- Is too large to fit into memory.
	- Is too slow.
	- Doesn't scale properly.
	- Has security vulnerabilities.
	- Has become outdated.
## Testing and validation
- Given a set of data to train a model it is common to create both a training and a test set out of it.
- **Training set**: data used to train a model with. Usually 80% of the total data set.
- **Test set**: data used to test a models performance with. Usually 20% of the total data set.
- **Generalization error** or **out-of-sample error**: error rate on instances that are not part of the training set. **???**
- If **training error** is low, but the **generalization error** is high, it means that your model is overfitting. **??? training error?**
### Hyperparameter tuning and model selection
- When in doubt during model selection between two models, one option is to train them both and compare how well they generalize the test set.
- **Holdout validation** 
	- Hold out part of the training set, thereby creating a reduced training set and  a **validation set** (or **development set** or **dev set**).
	- Train multiple models with various hyperparameters on the reduced training set.
	- Select the model that performs best on the validation set.
	- Then train the model on the full training set (reduced training + validation).
	- Evaluate the model on the test set to get an estimate of the generalization error.
